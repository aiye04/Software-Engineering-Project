# 一、项目概述

## 1.1 项目背景

本项目为广东东软学院软件工程课程综合型实验项目，旨在开发"网络安全战队协同与教学管理平台（CTF Team & Coach Hub）"。目标用户包括战队的指导老师、系统管理员及全体队员（队长、核心队员、普通队员、预备队员）。

## 1.2 核心功能模块

系统包含以下七大功能模块：

1. 多角色权限中心（RBAC）：支持管理员、老师、队长、核心队员、普通队员、预备队员六种角色
1. 教学督导看板：教师专属仪表盘，含数据概览卡片、能力雷达图、成长趋势图
1. 后台管理中心：系统管理员专属，用户管理、数据字典维护、系统监控与备份
1. 赛事协同中心：比赛日历、实时作战面板（WebSocket）、题目认领、赛后复盘流
1. 战队知识库：WriteUp结构化存储、分类标签、全文搜索、版本管理、权限控制
1. 能力发展体系：学习路径图、内部训练题集、个人技能档案
1. 资源与门户：公告栏、常用资源链接、新人引导页

# 三、各阶段详细开发指南

## 阶段一：项目搭建（第1周）

### 3.1.1 前端项目初始化

1. 使用 Vite 创建 Vue 3 + TypeScript 项目：npm create vite@latest ctf-hub-frontend -- --template vue-ts
1. 安装依赖：vue-router、pinia、axios、element-plus、echarts、vue-echarts
1. 配置目录结构：src/views（页面）、src/components（组件）、src/api（接口）、src/store（Pinia）、src/router（路由）
1. 配置 axios 拦截器：请求拦截添加 JWT Token，响应拦截处理 401 跳转登录页
1. 配置路由守卫：未登录跳转登录页，已登录根据角色权限动态过滤路由
1. 封装全局 Layout 组件：顶部导航栏 + 左侧菜单 + 内容区，菜单根据角色动态渲染
### 3.1.2 后端项目初始化

1. 使用 Spring Initializr 创建 Spring Boot 项目，勾选：Spring Web、Spring Security、Spring Data JPA、MySQL Driver、Redis、WebSocket、Lombok、Validation
1. 在 application.yml 中配置：数据源、Redis、服务端口（8080）、CORS 跨域
1. 创建基础包结构：controller、service、repository、entity、dto、config、security、websocket、common
1. 配置 Spring Security + JWT：实现 JwtTokenProvider、JwtAuthenticationFilter、SecurityConfig
1. 创建统一响应类 Result（code、message、data）和全局异常处理器
### 3.1.3 数据库初始化

根据设计规格说明书3.5节，共需创建11张核心表，建议编写 init.sql 脚本一次性执行。

五大业务域：

1. 用户权限域：sys_user（用户表）
1. 赛事协同域：competition（赛事）、competition_problem（赛题）、cooperation_log（协同日志）
1. 知识库域：writeup（解题报告）、writeup_category（分类）、writeup_tag（标签关联）
1. 训练管理域：training_task（训练任务）、training_submission（提交记录）
1. 通知日志域：notification（通知）、notification_read（已读）、operation_log（操作日志）
### 3.1.4 Docker 环境搭建

1. 编写 Dockerfile（多阶段构建：Maven编译 + JRE运行），暴露8080端口
1. 编写 docker-compose.yml，定义4个服务：nginx（80/443）、app（Spring Boot）、mysql（3306）、redis（6379）
1. 配置 Nginx 反向代理：静态资源直接返回，/api/* 转发到 Spring Boot，/ws/* 转发并配置 Upgrade 头以支持 WebSocket
1. 验证：docker-compose up -d，确认四个服务均正常启动

## 阶段二：基础模块开发（第2-4周）

### 3.2.1 用户认证系统（第2周）

这是整个系统的基石，需优先完成并确保安全可靠。

1. 后端注册接口 POST /api/auth/register：接收用户名、密码、确认密码，密码 BCrypt 加密后存储
1. 后端登录接口 POST /api/auth/login：验证账号密码，成功返回 JWT Token（含 userId、role、exp）
1. JWT Token 刷新机制 GET /api/auth/refresh，支持无感续期
1. 前端登录页面：表单校验（用户名必填、密码长度 ≥ 6）、错误提示、记住我功能
1. Pinia 存储用户信息和 Token，页面刷新时从 localStorage 恢复登录态
1. 路由守卫：未登录跳转 /login，已登录根据角色信息过滤可见菜单
### 3.2.2 RBAC 权限控制（第3周）

1. 设计权限模型：用户 → 角色（admin/teacher/captain/core/member/trainee）
1. 后端 Controller 方法添加权限注解，根据角色限制接口访问
1. 后端编写全局权限校验，越权访问统一返回 403
1. 前端根据用户角色动态生成左侧菜单，使用 v-if 控制按钮/操作显隐
1. 封装 v-permission 自定义指令，接收角色数组，判断当前用户是否有权限
### 3.2.3 用户管理模块（第3-4周）

管理员专属功能，包含完整的 CRUD 操作。

1. 用户列表查询 GET /api/admin/users，支持分页、搜索（用户名/真实姓名）、按角色筛选
1. 新增用户 POST /api/admin/users、编辑 PUT /api/admin/users/{id}、删除 DELETE /api/admin/users/{id}
1. 批量导入 POST /api/admin/users/batch-import，接收 Excel 文件，使用 Apache POI 解析
1. 批量导出 GET /api/admin/users/export，生成 Excel 下载
1. 重置密码 PUT /api/admin/users/{id}/reset-password、启用/禁用 PUT /api/admin/users/{id}/status
1. 前端：用户列表页（Table + 分页 + 搜索栏 + 批量操作）、用户表单弹窗（角色下拉 + 状态开关）、批量导入弹窗（文件上传 + 预览 + 确认）

## 阶段三：核心业务模块开发（第5-8周）

### 3.3.1 教学督导看板（第5-6周）

教师的核心指挥中心，数据可视化是重点。

- 【后端】团队数据概览接口 GET /api/dashboard/overview：成员数、活跃度、比赛参与率、新增 WriteUp 数
- 【后端】能力雷达图接口 GET /api/dashboard/radar：返回各方向能力评分（Web/Pwn/Crypto/Misc/Reverse）
- 【后端】成长趋势接口 GET /api/dashboard/trend：指定时间段内的技能增长、贡献度变化
- 【前端】页面布局：顶部数据概览卡片行（4-6个指标卡片，含数值和趋势箭头）
- 【前端】ECharts 雷达图：各方向能力水平，填充多边形，带图例
- 【前端】ECharts 折线图：成长趋势，支持时间范围切换（近7天/30天/本学期）
- 【前端】成员能力排行榜：综合评分排名表格
- 【优化】使用 Redis 缓存看板统计数据（TTL 5分钟），减少数据库查询压力
### 3.3.2 赛事协同中心（第6-7周）

核心作战模块，WebSocket 实时通信是关键技术难点。

- 【后端】比赛 CRUD /api/competitions，支持状态筛选（upcoming/ongoing/finished）
- 【后端】比赛日历 GET /api/competitions/calendar，返回月度赛事分布
- 【后端】赛题管理 /api/competitions/{id}/problems：添加赛题、更新状态、队员认领
- 【后端WebSocket】配置 Spring WebSocket + STOMP 协议，注册 /ws/collaboration 端点
- 【后端WebSocket】消息处理：接收 → 存入 cooperation_log → 广播给同场比赛在线用户
- 【后端WebSocket】状态同步：题目状态变更时实时推送更新（待解决 → 认领 → 已解决）
- 【后端】赛后归档：一键归档比赛数据，关联生成 WriteUp 模板
- 【前端】比赛列表页：卡片网格布局，状态颜色标签
- 【前端】作战面板：左侧题目看板 + 右侧实时协同区（消息流 + 输入框）
- 【前端】使用 SockJS + STOMP.js 管理 WebSocket 连接
- 【前端】消息渲染：v-for 渲染，新消息自动滚底，消息气泡区分发送者

### 3.3.3 战队知识库（第7-8周）

核心资产库，支持 Markdown 编辑和全文搜索。

- 【后端】WriteUp CRUD /api/knowledge-base/writeups，分页 + 分类筛选 + 标签筛选 + 关键词搜索
- 【后端】全文搜索：利用 MySQL FULLTEXT 索引对 content 字段检索
- 【后端】分类管理 /api/knowledge-base/categories：树形分类 CRUD，支持父子层级
- 【后端】权限控制：public（全员）/ internal（队员）/ private（作者），接口按角色过滤
- 【后端】浏览去重计数（Redis，30分钟内同用户不重复）+ 点赞 Toggle（Redis Set）
- 【前端】知识库首页：左侧树形分类 + 右侧 WriteUp 卡片列表
- 【前端】搜索栏：关键词搜索 + 分类/标签联合筛选
- 【前端】WriteUp 详情：Markdown 渲染（marked.js + highlight.js）
- 【前端】WriteUp 编辑器：Markdown 实时预览 + 图片拖拽上传

# 七、开发注意事项

## 7.1 安全要求（必须严格遵守）

1. 所有用户密码使用 BCrypt 加密存储，禁止明文保存
1. 前后端均需校验用户权限，不可仅依赖前端隐藏按钮
1. 所有 API 接口需验证 JWT Token 有效性，敏感操作记录 operation_log
1. 防止 SQL 注入：使用参数化查询（MyBatis #{} 或 JPA ?占位符），禁止字符串拼接 SQL
1. 防止 XSS 攻击：前端对用户输入转义，后端输出过滤
1. 生产环境必须使用 HTTPS，禁止 HTTP 明文传输
## 7.2 代码规范

1. 后端：遵循阿里巴巴 Java 开发手册，使用 Lombok 简化代码
1. 前端：ESLint + Prettier 统一风格，组件命名 PascalCase，文件命名 kebab-case
1. API 返回统一格式：{ code: 200, message: "success", data: {...} }
1. Git 提交格式：[模块] 简短描述，如 [auth] 实现JWT登录认证
## 7.3 性能优化建议

1. 看板数据使用 Redis 缓存，TTL 设定 5-15 分钟
1. 知识库列表分页查询，单页不超过20条
1. ECharts 图表数据超过1000点时启用 sampling: "lttb" 采样降频
1. 前端路由懒加载（() => import(...)），减少首屏加载体积
1. WebSocket：cooperation_log 表定期归档（>6个月数据迁移至归档表）
## 7.4 关键技术难点预研

- WebSocket + STOMP：建议在第4周搭建最小 Demo（一个聊天室）验证技术可行性
- ECharts 动态数据刷新：使用 watch 监听数据变化 + chart.setOption({...}, true) 合并更新
- JWT 无感刷新：在 axios 响应拦截器中判断 401 + 即将过期，自动调用 refresh 接口
- Markdown 编辑器集成：推荐 @toast-ui/editor（Toast UI Editor），支持预览+代码高亮+图片上传
- Docker Compose 网络配置：确保 app 容器能通过服务名（mysql、redis）访问数据库，而非 localhost
