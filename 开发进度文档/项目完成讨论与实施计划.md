## 1. 当前仓库读取结论

### 1.1 已有资料

当前仓库主要包含项目设计与进度资料，尚未包含可运行的前端或后端源码。因此，下一步不是“补几个页面”或“修几个接口”，而是需要从项目骨架开始落地实现。

已读取到的资料包括：

| 文件/目录 | 作用 | 对后续开发的价值 |
| --- | --- | --- |

### 1.2 项目目标复述

本项目要完成的是一个面向网络安全战队的协同与教学管理平台，核心目标是：

1. 让老师可以管理队员、查看训练和成长数据。
2. 让队长/队员可以协同参与 CTF 赛事、认领题目、记录讨论与复盘。
3. 让战队沉淀 WriteUp、训练任务、学习路径和资源链接。
4. 让管理员可以维护用户、角色、字典和系统运行数据。
5. 最终形成一个可部署、可演示、可验收的完整课程项目。

## 2. 我建议先和你确认的讨论点

为了避免一开始做得太大、最后无法交付，建议先围绕以下问题达成一致。

### 2.1 交付目标：完整系统还是课程可验收 MVP？

建议采用“先 MVP、再增强”的策略。

| 目标 | 建议 | 原因 |
| --- | --- | --- |
| 课程验收 | 优先保证 MVP 可跑通 | 老师验收通常更看重完整流程、演示效果、文档和部署 |
| 真实投入使用 | 在 MVP 后增强权限、搜索、统计、审计等细节 | 可以避免早期复杂度过高 |

**建议结论：第一阶段先做课程可验收 MVP。**

MVP 必须包含：

1. 登录注册 + JWT 鉴权。
2. 六类角色的基础权限控制。
3. 用户管理。
4. 赛事管理 + 赛题认领。
5. 知识库 WriteUp 增删改查。
6. 训练任务和提交记录。
7. 通知公告。
8. 简单数据看板。
9. Docker 或本地一键启动说明。

可延后增强：

1. WebSocket 实时协同。
2. Redis 缓存。
3. 高级全文搜索。
4. 复杂雷达图/趋势图。
5. HTTPS 证书。
6. 完整审计日志和数据备份。

### 2.2 技术路线：是否严格沿用原文档？

原计划的技术栈为：Vue 3 + TypeScript + Element Plus + ECharts，后端 Spring Boot + MySQL + Redis + WebSocket，部署 Docker + Nginx。

**建议结论：沿用原文档技术栈，不临时更换。**

原因：

1. 已有设计文档围绕该技术栈展开。
2. Vue + Spring Boot 适合课程项目展示。
3. Element Plus 能快速做出管理系统界面。
4. Docker Compose 方便最后部署和答辩演示。

### 2.3 先做哪些模块？

建议按依赖关系而不是按“看起来酷”的程度排序：

1. 项目骨架、数据库、统一接口格式。
2. 登录注册、JWT、角色权限。
3. 用户管理。
4. 赛事/赛题/WriteUp/训练任务这些核心业务 CRUD。
5. 看板和图表展示。
6. WebSocket、缓存、搜索等增强能力。
7. 测试、部署、文档、演示材料。

## 3. 功能范围拆分

### 3.1 角色范围

系统保留六类角色：

| 角色 | 权限定位 | MVP 需要支持的能力 |
| --- | --- | --- |
| 管理员 `admin` | 系统最高权限 | 用户管理、角色分配、系统基础配置 |
| 老师 `teacher` | 教学与督导 | 查看看板、发布训练/通知、查看提交 |
| 队长 `captain` | 战队协同组织 | 创建/管理比赛、分配题目、查看队员状态 |
| 核心队员 `core` | 主要参赛成员 | 认领赛题、提交 WriteUp、参与训练 |
| 普通队员 `member` | 常规成员 | 参与比赛、查看知识库、提交训练 |
| 预备队员 `trainee` | 新人成员 | 查看资源、完成训练、阅读公开知识库 |

### 3.2 模块优先级

| 优先级 | 模块 | 必须完成内容 | 可延后内容 |
| --- | --- | --- | --- |
| P0 | 项目基础设施 | 前后端脚手架、数据库、统一响应、异常处理、路由、Layout | CI/CD |
| P0 | 认证与权限 | 注册、登录、JWT、路由守卫、角色菜单 | 无感刷新、细粒度按钮权限 |
| P0 | 用户管理 | 用户列表、创建、编辑、禁用、角色分配 | Excel 导入导出 |
| P0 | 赛事协同 | 比赛 CRUD、赛题 CRUD、题目状态、题目认领 | WebSocket 实时消息 |
| P0 | 知识库 | WriteUp CRUD、分类、标签、Markdown 展示 | 全文搜索、版本管理 |
| P1 | 训练管理 | 训练任务、提交记录、评分 | 自动判题 |
| P1 | 通知公告 | 发布通知、通知列表、已读状态 | 消息铃铛实时提醒 |
| P1 | 教学看板 | 用户数、比赛数、WriteUp 数、训练完成率、简单图表 | 雷达图复杂指标、Redis 缓存 |
| P2 | 资源门户 | 资源链接、新人引导 | 热门文章推荐 |
| P2 | 系统增强 | 日志、备份、性能优化 | 生产级监控 |

## 8. 迭代计划

### 8.1 第 0 轮：项目补齐准备

目标：把当前“只有文档”的仓库变成可开发仓库。

任务：

1. 创建 `backend/` Spring Boot 项目。
2. 创建 `frontend/` Vue 3 项目。
3. 创建 `deploy/` Docker Compose 和 Nginx 配置。
4. 创建 `docs/` 接口、数据库、测试、部署文档目录。
5. 补充 `.gitignore`、`README.md`、`.env.example`。

验收标准：

1. 后端可以启动并返回健康检查接口。
2. 前端可以启动并显示基础 Layout。
3. Docker Compose 至少能启动 MySQL 和 Redis。

### 8.2 第 1 轮：认证权限闭环

目标：任何业务页面都基于登录态和角色权限访问。

任务：

1. 实现用户表和初始化管理员账号。
2. 实现登录接口、JWT 生成和验证。
3. 前端实现登录页、Token 保存、路由守卫。
4. 实现角色菜单。
5. 实现用户管理基础 CRUD。

验收标准：

1. 管理员可以登录。
2. 非登录用户访问业务页会跳回登录页。
3. 管理员可以创建老师和队员。
4. 不同角色看到不同菜单。

### 8.3 第 2 轮：核心业务闭环

目标：让赛事、知识库、训练任务都能完成基础流程。

任务：

1. 比赛 CRUD。
2. 赛题 CRUD、认领、状态更新。
3. WriteUp CRUD、分类、Markdown 展示。
4. 训练任务发布、提交、评分。
5. 通知发布和阅读。

验收标准：

1. 队长可以创建比赛和赛题。
2. 队员可以认领题目并更新状态。
3. 队员可以提交 WriteUp。
4. 老师可以发布训练并评分。
5. 用户可以查看通知并标记已读。

### 8.4 第 3 轮：看板与演示优化

目标：让系统“看起来完整”，适合答辩演示。

任务：

1. 实现统计卡片：用户数、比赛数、WriteUp 数、训练完成率。
2. 实现 ECharts 图表：训练趋势、题型分布、角色分布。
3. 首页整合近期比赛、最新通知、最新 WriteUp。
4. 补充样例数据。
5. 优化页面样式和空状态。

验收标准：

1. 登录后首页有真实数据。
2. 看板图表能展示统计结果。
3. 演示路径完整顺畅。

### 8.5 第 4 轮：增强与收尾

目标：补足加分项和交付材料。

任务：

1. WebSocket 协同消息。
2. Redis 缓存热点看板数据。
3. 知识库全文搜索。
4. 操作日志。
5. 单元测试和接口测试。
6. 用户手册、部署手册、测试报告、演示 PPT。

验收标准：

1. Docker 部署可用。
2. 主要接口测试通过。
3. 演示文档齐全。
4. 项目可以被他人按文档启动。

## 12. 风险与取舍建议

| 风险 | 表现 | 取舍建议 |
| --- | --- | --- |
| 时间不足 | WebSocket、缓存、全文搜索做不完 | 先保证 CRUD 和演示闭环 |
| 前后端联调慢 | 接口字段反复改 | 先写 `docs/api.md`，前后端按文档并行 |
| 数据库后期改动大 | 表结构频繁变化 | 使用初始化 SQL 或 Flyway 迁移脚本 |
| 页面太空 | 演示效果差 | 提前准备种子数据 |
| 权限复杂 | 每个按钮都要判断 | MVP 先做菜单级和接口级权限 |
| 部署失败 | 答辩现场启动不了 | 准备本地启动方案和截图/视频备份 |

## 14. 当前建议结论

结合仓库现状和原始进度文档，我建议下一步按以下顺序推进：

1. 先提交本计划文档，明确范围和优先级。
2. 下一次开发从“项目骨架”开始，而不是直接写业务页面。
3. 优先做课程验收 MVP，保证登录、权限、用户、赛事、知识库、训练、通知、看板能串起来。
4. WebSocket、Redis、全文搜索作为增强项，等基础闭环稳定后再做。
5. 每完成一个模块就提交一次，并同步更新 README、接口文档和测试记录。

如果只能选择最短路径完成项目，建议路线是：

```text
项目骨架 → 登录权限 → 用户管理 → 赛事赛题 → 知识库 → 训练通知 → 看板 → 部署文档 → 测试与演示
```
